# Claude Code hooks — the package-script interpreter

How the deck-host ask reads what a command would run, for whoever edits `scripts/claude-hooks/script-runs.mjs` (moved out of `rules-bash.mjs` with its code in #1590). Which commands ask, the names that ask whatever reads them, and which tree counts as linked are the rule's decisions, in *The integration tree and deck-linked trees* of `@.claude/rules/hook-internals.md`; the names there are the floor, for when nothing can be read. Why the interpreter reaches as far as it does, and when it should grow, is in the module's header.

## Where a script's command line comes from

A pnpm or npm script, a `node --run` and a turbo task are expanded (`deckFindings`) unless their name already asks: a relink's or a watch's name ends the judgement, a restart's does not, so a `restart:x` whose body relinks still asks (#1737). Every expanded npm or pnpm script is read with its `pre<name>` and `post<name>` scripts (`bodyLines`), whatever it is called, looked up under the name the script was found by, since npm runs them and pnpm may — a script pnpm would not run can only over-ask; `node --run` runs none, so none are read for it. The command line is read from the nearest package.json at or above the directory the script runs in (`ctx.scriptsAt`), or — for a turbo task — from every `packages/*` package of the tree (`ctx.workspaceDirs`, filters not read, so it over-reaches), or for a pnpm `--filter` / npm `-w` from the packages it picks (`runManifests`): a name with or without its scope, a path or `{…}` location exactly, and anything the hook cannot resolve — `-r`, a glob, a dependency or since query, an exclude-only list, npm `--workspaces` — over-reaching to every package plus the root. That line is judged by the same rule in the package's directory, recursively, with `\` read as `/` (cmd.exe's separator). The trail of `<dir>\0<script>` keys is the cycle guard and the depth bound (8, `MAX_SCRIPT_DEPTH`); past the bound a name is all that is judged, so a command that holds a restart and had a body left unread there asks (`deckFindings`): that body may relink, or run the restart again around a ring longer than the bound. A command with no deck finding stays prompt-free past the bound. When the guard cuts a cycle, at the depth bound too, everything the body of the script that runs itself found is a `watch` ("again every time it runs itself"), whatever the script is called; a cycle that finds nothing still finds nothing. A script is looked up by its name as written, else with its leftover escapes gone, as its kind is judged. A missing script or an unparsable package.json leaves the run judged by its name. pnpm's own commands (`install`, `add`, …) are never read as scripts, and pnpm's `verifyDepsBeforeRun` install is not modelled.

A pnpm `/<regex>/` script selector is one run per script name it matches in those manifests, and one more for a script literally named after the pattern (`selectedRuns`); one the hook cannot read, an invalid pattern or no manifest, asks.

## Arguments a runner passes on

The arguments a runner passes on (`pnpm <s> -- --restart`, `npm run <s> -- …`, `node --run <s> -- …`, turbo's after `--`) are appended to the expanded line, so a wrapper cannot hide `integration-build.mjs --restart`; a word there the hook cannot read (`$`, a backtick, `$(…)`, `%X%`, brace expansion, a glob, a PowerShell `@` splat) is a restart finding, since it may be that flag, and so is `--restart` written escaped (`--re\start`, a PowerShell backtick, cmd's `^`), which is compared unescaped. Like every restart, it passes unless it runs over and over. A plain branch name containing `restart` makes no finding.

## Runners, shells and watch hooks inside a line

`node`, `pnpm`, `npm` or `npx` behind a runner (`pnpm exec node`, `npx pnpm`, `npm exec npm run …`) is read as it is at command position. A shell wrapper's command string (`bash` / `sh` / … `-c`, `cmd /c` / `/k`, `powershell` / `pwsh -Command` or `-EncodedCommand`, `eval`, `Invoke-Expression`, `npx -c`, pnpm's `-c` / `--shell-mode` before or after `exec`, npm's `--call` / `-c` anywhere) is a command line judged recursively in its own shell (`wrapperRuns`), while a quoted string any other command takes (`git commit -m`, `echo`) is not. Which word is that string is read from the shell's own option spec — `readCommand` over `shellSpec(name)` in `shell-lexer.mjs`, the one table of each shell's valued options, string switch and positional switch, and the same walk the lexer places a shell-fed string with (#1634) — so `bash -eo pipefail -c '…'`, `fish -d 3 -c '…'`, `fish -c'…'`, `pwsh -ep Bypass -c "…"`, `pwsh -c"…"` and `cmd /d /s /c "…"` all reach their string, every lexer match inside it is skipped because this reader judges the string whole, and the two cannot disagree. The reader takes the command's words with their quotes (`commandWordsRaw`), since the walk needs them to tell `-c"…"` from a flag cluster, and decodes a word whole as bash reads it (`wordText`: quotes, escapes and `$'…'`) only once the walk has chosen it — whole, because a `&&`, `;`, `|` or newline the quotes hold is the string's own, which the shell handed it splits with its own `cd`s (#1634, CodeRabbit CLI round 5: decoding with `commandWords` ended `sh -c 'cd ../x && pnpm dev:voices'` at the `&&`, and the lexer's own match of the `pnpm` after it — at command position in the raw text, since the mask is set aside over the element — was judged at the session cwd, the wrong tree). Every runner's words are read whole the same way, since the lexer's `args` end at that `&&` too, and a word a runner hands a shell (`pnpm exec sh -c '…'`) arrives decoded and is never split again. Which lexer matches are the reader's: the first word of a string a shell at command position feeds, by the kind the lexer gives it, and any match inside a string whose decoded text is a line the reader has already judged — the commands are read in order of position, so the string a runner hands a shell, whose shell the lexer does not know, is covered too. A string no reader judges (`sudo`'s, `trap`'s, `watch`'s, `su`'s, a mention beside a shell word) keeps the lexer's matches. Typed, an `eval`, an `Invoke-Expression` where PowerShell runs it, a `-EncodedCommand` and a script a shell reads from a stream (a pipe, a here-string, a heredoc, a process substitution, `/dev/stdin`, PowerShell's `-`) never reach this reader: the lexer's stopping rule refuses them first (#1659, `hook-internals.md`). The stopping rule judges only the typed command, so a text this reader reads itself (a runner's shell string, a package script's body, a rollup hook) may still hold one: `deckReach` asks `refusedForms` of each such text and asks when it holds one, naming the form, since the hook cannot read what that text runs (an `unread` finding). Known gap: fish's `-C` / `--init-command` string, which the lexer reads, is not yet read here.

A `rollup` watch hook (`--watch.onStart`, `onBundleStart`, `onBundleEnd`, `onEnd`, `onError`, `=`-attached or the next word, any case or kebab form) is a command line too, judged recursively; this rule splits words shell-style (`shell-lexer.mjs`'s `shellWords`) so a quoted hook value stays one word.

## What a finding is

Each finding is a `restart`, a `relink`, a `watch` or an `unread` (`FINDING_KINDS`), and the rule asks when any is not a restart. One more, `lost`, is no prompt: a relink that acts only in a linked tree, run where a `cd` ahead of it leaves the tree unknown (#1646), is refused before the ask, since no confirmation can say which hosts it relinks. A script is judged by what it reaches, whatever it is called: a restart passes and a relink asks. A restart run over and over is a `watch` and asks, its text saying why (`repeated`): through a rollup watch hook or `turbo watch` (on every rebuild), as a command `watch` reruns or any command in the string `watch` is handed (found by the lexer's record of that quote, since it marks only the string's first word), or inside a bash `while` / `until` / `for ((…))` / `select` loop or a PowerShell `while` / `for` / `do` loop, a labelled `while` or `for` included — a labelled `do` is not read, since the lexer takes the label for bash's `:` builtin (#1739) — (`repeatsAt`, `loopSpans`, read from the lexer's mask, a loop word counting only at command position, past keywords that are at command position themselves, and a `!` counting only at command position and never before a `done`; where a shell is fed the mask is set aside, so a loop word or bracket inside a string is skipped). A bash `for … in` or a PowerShell `foreach` runs over a list, bounded, and its restart passes. cmd.exe's `for /l` and `yes | xargs` are not read: the reader grows when a real command slips past. So the Stream Deck plugin package's `watch`, whose `rollup --watch.onEnd` runs `streamdeck restart`, asks while a plain `build` passes.
