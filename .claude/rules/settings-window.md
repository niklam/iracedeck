# Settings Window (#992)

The dedicated, full-size settings window that owns the plugin-global settings. It is **not a Property Inspector**: it is a page the plugin process serves over loopback and opens as a chromeless browser app window — but it reuses the PI framework verbatim (`sdpi-components.js`, `pi-components.js`, the `global-*.ejs` partials, every `ird-*` component), so a control that works in a PI works in the window unchanged. Website docs: `docs/features/settings-window.md`.

## Rules

1. **Reuse, don't fork.** New global settings go in a `global-*.ejs` partial (or one of the split group partials below) so both surfaces get them. Never author a global control only in the window or only in a PI.
2. **`accordion.ejs` has two modes.** Pass `settingsWindow: true` at a top-level include and it renders a flat `.ird-sw-card` instead of `<details>`; EJS copies include data into nested includes, so the `global-*.ejs` partials forward it without changes. `locals.foo` inside a partial reads include parameters (the compile plugin no longer shadows EJS's `locals`).
3. **The Common Settings groups are partials**: `global-common-{window-focus,simhub,dual-press,replay,chat,updates,diagnostics}.ejs` (items only). `global-common-settings.ejs` assembles them with headings into the PI's one accordion; the window places them on tabs. Same for the Race Engineer block: `race-engineer-settings.ejs`, `race-engineer-callouts.ejs` (owns its list computation), `setup-warning-patterns.ejs` — `pit-crew.ejs` wraps them in its three accordions (same `accordionId`s), the window in cards. Tests render the REAL partials and pin every setting key.
4. **Write only what changed.** sdpi saves its _whole_ global object on every change; the fake host diffs it against the current cache with deck-core's `sameValue` (string forms equal parsed values) and writes only the differing keys. A full-object write marks every key pending and lets the #896 overlay misread a later foreign write that restores a previous value as a stale echo — observed as a PI edit being rolled back to the window's value. Residual: the one key the user changed in the window can still hit this if flipped straight back in the PI before the host confirms; that is #896's design and the argument for #993.
5. **Things a PI can't do the same way in the window** — each has a window-mode path keyed on `window.__irdSettingsWindow`:
   - SimHub reachability/roles: a direct fetch is cross-origin (no CORS) → `simhub-probe.ts` uses `GET /simhub/roles`, answered from the plugin's own SimHub service. `key-binding-input.ts` goes through the probe (a structural test forbids a private fetch).
   - Test buttons: no action context → `ird-audio-test` with a `preview="radar|voice|background"` attribute sends `sendToPlugin {event:"audioPreview", kind}`; the plugin runs `runAudioPreview` (`iracing-actions/src/audio/audio-previews.ts`), the same runner the Pit Crew action calls.
   - Profiles: no device → `ird-deck-device-select` (populated from the `_deckDevices` passthrough global the Elgato plugin publishes, like `_audioDeviceList`) + `ird-profile-switch device-from="<select id>"`; no choice → no send. Elgato build only (`profiles` flag), gated at compile time.
6. **Passthrough keys the window introduces**: `_settingsWindowBounds` (validated, sanity-bounded), `_deckDevices`. Both plugin-written; not user settings.
7. **Ulanzi normaliser trap:** `ulanzi-client.ts` `normalizeFrame` **drops** any `sendToPlugin` whose payload isn't a known marker. A new PI→plugin command on Ulanzi needs a marker added there (`openSettings` was), not just an adapter listener.
8. Brand: accent `#ce2128`, the header shows `iracedeck-logo.png` (committed in `pi-components/browser/` beside the vendored sdpi file — that `.gitignore` is `browser/*` with negations, since git can't re-include a file under an ignored _directory_).

## Verifying a change

`pnpm build` then check the built `ui/settings-window.html` per plugin: bridge script present exactly once and before `sdpi-components.js`; the _other_ bridge absent; the expected controls present (e.g. `grep -c '<ird-key-binding'` = 238). For a partial split, snapshot the compiled PI HTML before and prove it is byte-identical modulo whitespace after. Then the manual round-trip on hardware: change a setting in the window → visible in a PI, and back — and the plugin log (debug on) shows which write moved a key.
