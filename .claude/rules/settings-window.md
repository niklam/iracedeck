# Settings Window (#992)

The dedicated settings window that owns the plugin-global settings. It is **not a Property Inspector**: the plugin serves it over loopback and opens it as a chromeless browser app window, but it reuses the PI framework verbatim (`sdpi-components.js`, `pi-components.js`, the `global-*.ejs` partials, every `ird-*` component), so a control that works in a PI works here unchanged. Website docs: `docs/getting-started/settings.md`.

The server starts from the plugin's **store-ready startup block** (`ensureStarted()`, or the first `open()`) and lives for the process; on the fail-closed unreadable-file path that block never runs, so nothing starts and no channel is published. Its `_settingsChannel` (port + token) reaches the deck host through the once-per-start mirror, every action PI talks to the same server through its bridge, and so window ↔ PI ↔ PI edits all land in the plugin-owned file and show live everywhere. The mirror, the PI router's bootstrap and fallback, and run-scoped keys are owned by `@.claude/rules/global-settings.md`.

## Architecture (where each piece lives)

| Commands | `deck-core/src/settings-window-commands.ts` | `createSettingsWindowCommandHandler` validates and routes `sendToPlugin` payloads. |
| Launcher | `deck-core/src/settings-window-launcher.ts` + `chromium-browser.ts` | Finds Edge/Chrome/Brave (App Paths, then well-known paths; memoized), spawns a detached app window, falls back to the host's `openUrl`. |

### Load-bearing details

- **Guard: token first, then `Origin`, then cookie** (#993). A valid token authorizes whatever the `Origin` (PIs are `file://`/`null` or host-served). A token-less request must match the loopback origin exactly when it sends one before its cookie is looked at — the DNS-rebinding mitigation. **Never emit a CORS header.**
- **The server never throws out of a request or upgrade listener** — malformed target or escape → 400/404, the handler is wrapped, every accepted socket gets an `error` handler; a throw there ends the plugin process. `onUpgradeDecision` feeds the controller's debug `Settings socket accepted/rejected …` line.
- **Session cookie**: the URL token covers only the first navigation, so `/` sets `ird_sw_<port>=<token>; SameSite=Strict; HttpOnly`. The name is **port-scoped** because the three plugins' windows share one browser profile.
- **The fake host never echoes a `setGlobalSettings` to the socket that sent it** (the parsed echo would refill a just-cleared field with its default under the cursor) and skips a push equal to that socket's last one; other sockets and plugin writes are pushed, and an explicit `getGlobalSettings` is always answered. Rule 12 follows from it.
- **Commands never take a path from the page.** `windowBounds` → `_settingsWindowBounds`; `switchToProfile` needs an **explicit `deviceId`**; `audioPreview` passes its kind through (the runner owns the allow-list); `openSettingsFolder` / `openVoicePacksFolder` / `voicePackRefresh` take nothing — the handler uses its injected `storePath` / `voicePacksPath`, the latter named once per plugin and shared with the scanner. `voicePackInstall` / `voicePackRemove` (#1100) take a pack **id** checked against the manifest/catalog kebab-case rule, because an id becomes a directory name. `enableFeature` (#1061) goes through `enableFeatureWrites`, which writes the Race Engineer's gate AND startup-policy keys from `FEATURE_STARTUP_GATES` in ONE call — the gate alone reverts on the next start for pre-#1007 installs.
- **Launch**: `--app=<url> --user-data-dir=%LOCALAPPDATA%\iRaceDeck\settings-window-profile --window-size/--window-position`, detached. **The dedicated profile is load-bearing** — without it a running browser swallows the launch and ignores the size. The `openUrl` fallback also covers an asynchronous spawn failure (`spawnApp` may return a promise). Launcher and Open folder are the plugin's only `child_process` uses.
- **`openUrl` resolving means "sent", not "opened"** — no host reports whether a page appeared. The launch result is a hand-off, the `settings-window-open` banner only catches an opener that rejects, and no usable browser reads as success. Don't substitute a proxy such as "no Chromium found": the plain-tab fallback is supported.
- **Controller**: concurrent first-callers share ONE in-flight start, `close()` awaits it (never orphans a server), a re-click never binds a second port. `onStarted` fires per actual start and is bound to `createSettingsChannelPublisher(...).publish`, so a late start is still published. Debug-log the origin, never the tokenised URL. It logs both outcomes of both stages and reports them via `onStatus` — only it knows WHICH stage failed, since `open()` starts the server first. A throwing hook is logged and swallowed.
- **Failure banner** (#1005, #1014): two ids because **placement is keyed by id** — `settings-window-server` (`error`, page-wide, top strip) and `settings-window-open` (`warning`, directly above the button). A failed START raises both plus a short button note pointing at the error; the evaluator returns a LIST and the reporter reconciles it against `settingsWindowWarningScope` (a server report speaks for both records, an open report only for its own, so a press never clears the page-wide error). The button note ships with the once-per-start host mirror (`publishUnavailable`), because with no service a press has no route to the PI. The error states that a channel-less PI falls back to the host copy and its edits are ignored. Both are run-scoped; the window's own page withholds both ids (it is served by that server). Every other id shows there, including `settings-file-rejected` (#1036) — the corrupt-file path reaches store-ready, so the server starts and the page is the likeliest place a user sees it.
- **Window bridge**: patches `WebSocket` during sdpi's synchronous `connectElgatoStreamDeckSocket` to open `ws://<host>/ws?t=<token>` with a synthetic identity, then restores; **no frame translation**. Sets `window.__irdSettingsWindow = true`, polls bounds (a move has no DOM event), **closes the window when the socket dies**.
- **PI bridge**: pre-defines `connectElgatoStreamDeckSocket`, so a one-shot interceptor for `ws://localhost:<port>` and `ws://127.0.0.1:<port>` hands sdpi a `PiSettingsBridgeSocket` (host socket + router) and restores the native constructor at once. On Ulanzi the bootstrap read is the write's scope plus this PI's `actionid` (or `PI_READ_ACTIONID`) while writes keep the blank plugin scope (#868) — **reads and writes do NOT share a scope** (#1039, `global-settings.md`).
- **Page**: body grid rows are **named** because the page's own `<ird-warnings data-auto except="…both ids…">` is the first body child (it suppresses `head-common`'s unfiltered injection). The key-bindings table dedupes by setting key.
- **Getting Started**: its parser is a sibling of the changelog's, not a reuse, and strict — an action id missing from the partial's map is a BUILD failure. The Profiles prose renders everywhere; the jump to that tab is gated (no such tab on Mirabox/Ulanzi).
- **What's New**: offline; `changelog.json` is picked up from `data/` with no rollup wiring; bullets are pre-escaped HTML emitted raw; the release matching the build's `version` (pre-release suffix stripped) gets an INSTALLED badge, and a build with no section says so.
- **Update check**: the PLUGIN, never the page (cross-origin, no CORS), fetches `https://iracedeck.com/changelog.json` (same `scripts/lib/changelog-data.mjs`), sanitizes bullets to `<strong>/<em>/<code>/<a href>`, keeps only DATED releases `semver.gt` the running version, caches 1 h (5 min after failure, single-flight), serves `GET /updates/status` gated on `updateCheck` read live. `ird-update-notice` renders into `#sw-changelog` and emits `ird-update-available` (sidebar UPDATE badge); it starts on DOMContentLoaded, since `pi-components.js` is a `<head>` script. Every failure renders nothing.
- **Open button** (#1024): a centred block like `.ird-docs-link`, never an `sdpi-item`; cog + label, `compact` size. Built on `defineSendToPluginButton` (`components/send-to-plugin-button.ts`) with `ird-open-folder` — new one-shot `sendToPlugin` buttons use that factory, dressed via `icon`/`size`, never a second design. In an action PI it closes the action's OWN settings, directly above `title-overrides` and OUTSIDE every surface-conditional wrapper (inside `#keypad-appearance` it vanishes on the dial surface); `action-settings-footer.ejs` owns this and `action-settings-footer-partial.test.ts` checks all 36 templates. `open-settings.ejs` is the single definition and carries the open-failure banner directly above it; `head-common.ejs` gives the top strip the matching `except`, so it renders once. The server banner is unfiltered.

## Rules

1. **The window is the only home for plugin-global settings** (#1003). New ones go in a `global-*.ejs` (or group) partial included by `settings-window.ejs`. Never author a global control in an action PI; the one exception is `key-bindings-section.ejs` — an action's OWN bindings, also listed in full on the Key Bindings tab.
2. **`accordion.ejs` has two modes.** `settingsWindow: true` at a top-level include renders a flat `.ird-sw-card` instead of `<details>`, and nested includes inherit it. **Exception:** an `include()` INSIDE another include's object literal (`include('accordion', { content: include('global-common-diagnostics'), … })`) runs in the page's scope — pass `{ settingsWindow: true }` explicitly or its `locals.settingsWindow` guards render nothing (#993). `locals.foo` reads include parameters.
3. **The Common Settings groups are partials**: `global-common-{window-focus,mouse-pointer,simhub,dual-press,replay,chat,updates,diagnostics}.ejs` (items only), placed on tabs; the Race Engineer block is `race-engineer-settings.ejs`, `race-engineer-callouts.ejs` (owns its list computation), `setup-warning-patterns.ejs`, as cards. Tests render the REAL partials and pin every key. **Scripts follow the split**: these controls' behaviour lives in `settings-window-scripts.ejs` (window only); `head-common.ejs` keeps only what BOTH surfaces need — a test guards both directions.
4. **Write only what changed — an optimisation, not a correctness guard.** sdpi saves its whole global object per change; the fake host diffs it against the cache with deck-core's `sameValue` (string forms equal parsed values) and forwards only differing keys. Keep the diff; don't rely on it for correctness.
5. **Things a PI can't do the same way in the window** — each keyed on `window.__irdSettingsWindow`:
   - SimHub: a direct fetch is cross-origin → `simhub-probe.ts` uses `GET /simhub/roles`; `key-binding-input.ts` goes through the probe (a structural test forbids a private fetch).
   - Test buttons: `ird-audio-test preview="radar|voice|background"` → `sendToPlugin {event:"audioPreview", kind}` → `runAudioPreview` (`iracing-actions/src/audio/audio-previews.ts`), the ONLY preview path.
   - Profiles: `ird-deck-device-select` (from `_deckDevices`) + `ird-profile-switch device-from="<select id>"`; no choice → no send. Routed through `ElgatoPlatformAdapter.switchToBundledProfile`, the PI's own dispatch. Elgato only (`profiles` flag, compile-time).
   - Bounds: the bridge reports a **settled** position (unchanged for one 1 s tick) plus a final one on `pagehide` — one write per drag. A window opened **fully off-screen** is pulled onto its nearest display with `moveTo` and a size-only report is persisted, so the next open gets default placement.
   - Storage (#993): `global-common-diagnostics.ejs` shows `_settingsStorePath` on **both** surfaces (disabled `sdpi-textfield`); **Open folder** (`ird-open-folder` → `openSettingsFolder`) renders only under `locals.settingsWindow`, since a PI's `sendToPlugin` goes to its action.
6. **Passthrough keys the window introduces** — plugin-written, not user settings; in the store and mirrored to the host once per start via `hostMirrorPayload`:
   - `_settingsWindowBounds` (validated, sanity-bounded), `_deckDevices`, `_settingsStorePath`.
   - `_voicePacks` (#1034, **run-scoped**): the whole last scan `{ packs, problems }` in ONE key, so a list never sits beside stale reasons. Row `voices` carry composite ids (`<pack id>::<voice id>`, #1144), never the bare manifest id. `managed` marks the one pack the plugin installs and refreshes (no Remove button); it comes from the plugin (`isManagedVoicePack`), never inferred in the page — a hand-placed folder at that id reads *Installed by hand* with no Remove. `dir` is where the pack was found; `provenance` is `catalog` / `bundled-seed` / `sideload` / `development` (#1143). `development` is never on disk — assigned from the root (the development voice root — `IRACEDECK_DEV_VOICES` or `dev.local.json`, see `platform-feature-flags.md`), so no folder can claim it and a release build never publishes it; that row shows a *Development build* badge and its `dir` in place of Remove (the plugin never deletes from a directory it did not create), with `managed` false. `dir` is rendered on that row only and is absent from the row identity a Remove is armed against.
   - `_voicePackStatus` (#1100, **run-scoped**): the catalog's last answer plus installs in flight or failed, in ONE key for the same reason; a settings key rather than a route, which would be a second auth surface. Its only consumer is that card — the PI banner and Pit Crew key status in the #1034 spec were NOT built.
   - `_voiceLabels` (#1034): composite id → the pack's name for it (`voiceDisplayLabels`, #1147), published in the SAME write as `_raceEngineerVoices` and persisted like it.
   - `_settingsChannel` is the exception: per-process, never in the store, only in the host mirror.
7. **Ulanzi normaliser trap:** `ulanzi-client.ts` `normalizeFrame` **drops** any `sendToPlugin` whose payload isn't a known marker, so a new PI→plugin command on Ulanzi needs a marker there (`openSettings` has one), not just an adapter listener. Only commands a **PI sends over the host socket** are affected; window commands arrive via the loopback fake host, and global settings are not `sendToPlugin` frames (only those on the bootstrap read and the fallback path still cross `translate.ts`).
8. **Shared browser helpers, never a private copy.** `window.__irdSettingsWindow` is read ONLY through `components/settings-window-context.ts` (`SETTINGS_WINDOW_FLAG`, `inSettingsWindow()`); the bridge's own copy of the name is pinned equal by `build/settings-window-constants.test.ts`. `sendToPlugin` goes through `components/sdpi-client.ts` (`sendToPlugin`, `getStreamDeckClient`).
9. **Brand**: accent `#ce2128`; header `iracedeck-logo.png`, favicon `iracedeck-icon.png` (#1156, `docs/superpowers/specs/2026-09-10-issue-1156-settings-window-favicon.md`), both committed in `pi-components/browser/` (`.gitignore` is `browser/*` with negations), exported as `SETTINGS_WINDOW_LOGO` / `SETTINGS_WINDOW_ICON` and in every plugin's copy list. The favicon is **this page's alone** — `head-common.ejs` and `settings.ejs` carry no `<link rel="icon">`; neither the wordmark nor the website favicon substitutes. The icon is a **fully opaque** 256×256 white square, the mark from `assets/iracedeck-logo-1024x1024-white.png` cropped to content at 90% width, an RGB PNG with **no alpha channel** (Windows draws Chromium's premultiplied pixels as straight alpha, darkening any transparency). **Keep the white background** — the mark's black checkers vanish on a dark taskbar. `settings-window-icon.test.ts` pins asset, link and copy lists, and refuses a non-square, sub-256 px or alpha-carrying icon.
10. **The What's New pane has exactly one runtime** (#1011, #1016). The compiled-in notes render newest-first with no script, fetch or scroll-into-view, so the pane works offline and never names a version the user lacks. The one exception is `ird-update-notice`, which asks the PLUGIN (never the website) and renders nothing it cannot answer. Keep new behaviour out; anything needing the network goes through the plugin. A `changelog.mdx` edit is stale here until `pnpm generate:changelog-data` runs (`@.claude/rules/changelog.md`).
11. **`open({ pane })` is a FRAGMENT, and the page's handler is a fail-soft** (#1061). `#<pane>` never reaches the server, so the auth model is untouched; the page reads it with `getElementById` (an id, not a selector) and falls back to its default tab, and a non-lowercase-slug value is dropped rather than interpolated (it reaches a browser command line). Because the fallback is silent, `GETTING_STARTED_PANE` (deck-core), `data-pane`/`id="pane-…"` (`settings-window.ejs`) and `SETTINGS_WINDOW_TABS` (`tabs.mjs`) move together; `tabs.test.mjs` pins both links.
12. **Never bind the same global setting twice on one page** (#1061). The writer gets no echo, so a second control on that key keeps its old value and writes it back when touched — each control correct and tested alone, the defect only in the pair. Point at the owning tab instead (a `data-jump` button, as Getting Started does for `changelogNotification`).
13. **One bridge per page** — `pi-settings-bridge.js` on Elgato/Mirabox action PIs, `ulanzi-pi-bridge.js` on Ulanzi action PIs, `settings-window-bridge.js` on `settings-window.html` only; two would double-patch `WebSocket`. `assertBridgeInjectionPlugin` throws, naming the file, unless every page that loads sdpi carries its expected bridge exactly once, immediately before `<script src="sdpi-components.js">`, and no other.

## Verifying a change

`pnpm build` (a green build proves bridge placement), then check each plugin's `ui/` for the expected controls (e.g. `grep -c '<ird-key-binding'` = 237, one per unique setting). For a partial split, prove the compiled PI HTML byte-identical modulo whitespace against a before-snapshot. Then on hardware with debug logging on: a window edit shows live in a PI, logs `Settings saved: <path>` and changes the file's **content** (not just mtime — every start re-saves); a PI edit shows live in the window and a second PI; after restarting the deck software every value is still there. A PI that fell back to the host path logs `iRaceDeck: …` in its DevTools console — check for that, not for a silently wrong value.
