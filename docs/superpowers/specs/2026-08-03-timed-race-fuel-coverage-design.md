# Timed-race fuel-coverage suppression + "enough fuel" reassurance — design (issue #880)

Approved 2026-08-03. Follow-up to #866 (which followed #838). Adds a timed-race remaining-laps estimate to the laps-of-fuel-left race-coverage suppression, resolves the three limitations deferred from the #866 review, and adds a positive "We have enough fuel to finish the race!" callout.

## Problem

The #866 race-coverage suppression only works in lap-limited races — timed races (`SessionLapsRemainEx` reads the `IRSDK_UNLIMITED_LAPS` sentinel) get only the final-lap latch and post-race gates. Observed in the field: "1 lap of fuel left, plan to box" while the white flag was already up in a timed race (the #772 latch only sets at the player's own S/F crossing under white, so the whole white-flag lap before that crossing was unguarded). Additionally, suppression today is silent — the driver never hears a positive confirmation that fuel is a non-issue.

## Decisions (user-approved)

1. **Reassurance trigger — replace the first suppressed warning.** `fuel.lapsLeft.raceCovered` fires once, exactly when the first laps-left warning (count ≤ 10, descending below the dedup floor) WOULD have fired but the coverage determination is positive. Silent if fuel never enters the warning band (no noise when fuel was never a topic). Re-arms on refuel (new stint) and whenever a real warning later fires (burn-spike arc: warning → reassurance → spike → warning → reassurance).
2. **Timed estimate — leader-aware upper bound.** Laps the player still runs AFTER finishing the current one:
   `timedRemaining = max(0, ceil((SessionTimeRemain + leaderLap − (1 − LapDistPct) × playerAvgLap) / playerAvgLap))`
   A timed race ends when the LEADER's clock expires plus their final crossing; the player then finishes their current lap. Overestimating remaining laps is the safe direction (warnings stay on a little longer). Leader pace: `CarIdxLastLapTime[leader]` → `CarIdxBestLapTime[leader]` → player's own average; leader from the canonical live order (`calculateFrozenRacePositions`, per `race-positions.md`).
3. **Player pace source — the existing #465 tracker.** `FuelLap` already records `lapTime` with the exact validity gating the estimate needs (out/in/tow laps excluded). `computeFuelStats()` gains `avgLapTime: number | null` over the same valid-lap window. No new tracker.
4. **Voice clips** — generated by Claude via the ElevenLabs pipeline; only the `default` voice exists today.

## The three #866 limitations

1. **Dual time+lap limits** — coverage = `coveredByLaps OR coveredByTime`; whichever limit ends the race sooner binds (the min of the two remaining distances).
2. **`SessionLapsRemainEx` race semantics — VALIDATED from captures (2026-08-03).** Six lap-limited race captures in `local/` with the player 1–3 laps down all show `SessionLapsRemainEx === SessionLapsTotal − leaderLapCompleted`: the counter is **leader-relative in races** (qualifying's player-relative reading, #776, does not carry over). This is the correct quantity for coverage: a lapped car takes the checkered when the leader does, so under equal pace the player's remaining crossings ≈ the leader's remaining laps, and the #866 `count >= raw − 1` bridge stands. In multiclass the overall leader is faster, so the reading overstates a slower player's remaining laps — suppression engages late, the conservative direction. Documentation corrected; no comparison change.
3. **White-flag latch reset** — new sticky per-session `TranslatorState.playerFinalLapStarted`, set wherever `whiteLastLapFired` is set but never re-armed when the White bit drops (a caution replacing the white mid-final-lap can no longer resurrect the box call). Preserved across the replay wipe; cleared per session.

## Architecture

All gating stays **diff-side** (`packages/sim-events-iracing/src/diff/fuel-laps-left.ts`), the #838/#866 invariant: scenarios keep filtering only on count/event.

- New diff input: `getLeaderLapTimeS: () => number | null` closure from the translator.
- Emission restructure: post-race / sticky-final-lap gates stay first and unconditional (no warning AND no reassurance there). Then `wouldWarn = count ≤ 10 && below floor`; if covered → maybe emit `fuel.lapsLeft.raceCovered` (latched via `fuelCalloutRaceCoveredAnnounced`), never advancing the warning floor (coverage re-evaluated every lap — a burn-rate spike still announces).
- New bus event `fuel.lapsLeft.raceCovered` (EmptySimEventPayload); scenario `pit-crew.fuel-laps-left-race-covered` (`family: "fuel"`, `WEIGHT.NORMAL`, `queueable: true`, radio-framed); pool `fuel-laps-left-race-covered` → `fuel/race-covered`; opt-in `calloutEnabledFuelLapsLeftRaceCovered` (default ON) riding the existing fuel-family closure — no `registerPitCrew` signature change.
- Clip: `fuel/race-covered-01.mp3` — "We have enough fuel to finish the race!"

## Out of scope

- Other voices (only `default` exists).
- Any change to the #866 unconditional final-lap/post-race trade-off (a genuinely-short estimate still stays silent there).
- Caution-pace modelling in the timed estimate (green-pace averages overestimate remaining laps under caution — the conservative direction).
