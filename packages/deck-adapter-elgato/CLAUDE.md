# @iracedeck/deck-adapter-elgato

Elgato Stream Deck adapter that implements `IDeckPlatformAdapter` from `@iracedeck/deck-core`. Bridges the `@elgato/streamdeck` SDK to the platform-agnostic interfaces.

## How It Works

`ElgatoPlatformAdapter` wraps the Elgato SDK:

- **`registerAction(uuid, handler)`** — Creates a bridge `SingletonAction` subclass that sets `override manifestId = uuid` directly — deliberately **not** via the `@action({ UUID })` decorator, whose `__esDecorate` helper emits `(this && ...)` code that is invalid in ESM. Do not reintroduce the decorator. Delegates all lifecycle methods (`onWillAppear`, `onKeyDown`, dial handlers `onDialRotate`/`onDialDown`/`onDialUp`, and `onTouchTap`) to the platform-neutral handler, through the per-context order below. One bridge per UUID: a second `registerAction` for the same UUID replaces the handler (the one registered when an event arrives is the one called) and adds no second SDK action, since the SDK cannot unregister one and two bridges would both enqueue every event on the shared order
- **Per-context event order (#1597)** — Every `BridgeAction` method hands its event to one deck-core `ContextEventOrder` per adapter (created on first use, logger scope `ContextEventOrder`) with `order.enqueue(ev.action.id, <kind>, task)`, synchronously inside the SDK callback and before any await — the SDK's emitter reaches the bridge in the same call stack as the host frame, so arrival order is fixed there. The task builds the deck-core event and calls the handler when it runs, as a non-async lambda, so an event that overlaps nothing still reaches the handler inside the SDK callback. The method returns the enqueue promise, so the SDK's route sees the handler's rejection as before; a dropped event (a context that is not live) resolves to nothing. Appear, disappear and settings changes are exclusive; input waits only for them, so two presses still run concurrently. A `willAppear` for a context that is already live at arrival is enqueued as an exclusive `didReceiveSettings` carrying that frame's settings (built with `wrapEvent({ action, payload })`) and logged at debug on the `Lifecycle` scope — never a second appear, never dropped; the SDK is not expected to send one, but the rule is every adapter's. A Neo Infobar instance returns before the enqueue, so it never becomes live. The adapter keeps no per-context state of its own (the SDK's action store carries controller and settings), so no bookkeeping sits in the tasks. Rules and log lines: `deck-core/src/context-event-order.ts`; design record: `docs/superpowers/specs/2026-11-02-issue-1597-lifecycle-event-ordering.md`
- **Broadcasts gated on the order's liveness** — `onKeyDown` / `onDialDown` / `onDialRotate` subscribe to the SDK-wide listeners, which run in the same emit as the action routes (so at arrival), and call back only when `order.isLive(ev.action.id)`. The SDK already passes only a context in its action store; the gate is the adapter's own, so the contract does not rest on the SDK's store
- **The ordering contract suite** — `adapter.context-order.test.ts` runs deck-core's `CONTEXT_EVENT_ORDER_SCENARIOS` (`@iracedeck/deck-core/testing`) through a fake SDK that models `@elgato/streamdeck`'s dispatch — one emitter calling every listener in registration order without awaiting, the per-action routes in the SDK's order filtered by manifest id, the SDK-wide listeners — and deliberately no action store, so the adapter's own gate is what is measured. It also holds the Elgato-specific checks: the synchronous fast path, the route seeing a handler's rejection, Neo Infobar contexts never live, one bridge per UUID. `scripts/deck-adapter-order-contract.test.mjs` fails the package if the suite run disappears. Tests that drive an input or settings event straight at the bridge appear the context first, or the event is dropped
- **Event wrapping** — Converts Elgato events (`WillAppearEvent`, `KeyDownEvent`, etc.) to deck-core events (`IDeckWillAppearEvent`, `IDeckKeyDownEvent`, etc.) via `ElgatoActionContext`. The dial rotate event is wrapped with `ticks` and `pressed` (rotate-while-held) by `wrapDialRotateEvent`, and the encoder touchscreen tap via `wrapTouchTapEvent` (`tapPos`, `hold`).
- **Stream Deck+ dial bridging** — `ElgatoActionContext` bridges `isDial()`, `setFeedback(payload)`, `setFeedbackLayout(layout)`, and `setTriggerDescription(descriptions)` to the SDK `DialAction` (forwarding `DeckFeedbackPayload` as the Elgato `FeedbackPayload`); these are guarded so they no-op when the underlying action lacks them. `dialCanvas()` is the 200×100 `sd-plus-strip` profile on an Encoder context (`null` on a key), and `setDialCanvas(dataUri)` sends it as `setFeedback({ box })` — `DIAL_CANVAS_KEY`, the one pixmap every dial layout under `layouts/` carries (#1013). The context also exposes `deviceId`/`deviceType` getters and `showAlert()` (present on `KeyAction` only — dials have no warning indicator).
- **Profile-switch wiring (Elgato-only)** — The constructor wires `sd.ui.onSendToPlugin` → `handleSendToPlugin`, routing the PI "Stream Deck Profiles" accordion's `switchToProfile` messages through the deck-core `requestProfileSwitch` singleton (not `this.switchToProfile` directly, so the switch lands in the per-device profile history, #762), after resolving the accordion's clean display names to device-suffixed manifest names via `deviceProfileName` (#753). The other adapters never receive this message.
- **`switchToProfile(deviceId, profile?, page?)`** — Delegates to `sd.profiles.switchToProfile`. A not-yet-installed profile triggers the Stream Deck app's install prompt — this is how the bundled profiles get installed and updated.
- **`openUrl(url)`** — `sd.system.openUrl`.
- **`setLogLevel(level)`** — forwards to the SDK logger (`sd.logger.setLevel`), mapping the `@iracedeck/logger` enum to the SDK's level string: `Debug` and `Trace` → `"debug"`, `Info` → `"info"`, `Warn` → `"warn"`, `Error` and `Silent` → `"error"`.
- **`logLocation`** — `{ kind: "file", path }` for `<cwd>/logs/<plugin UUID>.0.log` (`elgatoPluginLogFile()`); the shared bootstrap hands it to the main-thread watchdog and puts the CPU profiles beside it.
- **`WillDisappearEvent` special case** — Elgato's `ActionContext` lacks `setImage`/`setTitle`/`isKey` (and dial methods), so `wrapDisappearEvent()` provides no-op stubs
- **`createLogger(scope)`** — Wraps `streamDeck.logger.createScope()` via `createSDLogger()`
- **Global settings: one fan-out, two sources** — `onDidReceiveGlobalSettings(cb)` records the callback and subscribes to the SDK event once; `getGlobalSettings()` awaits the SDK's `settings.getGlobalSettings()` promise and hands its result to the same subscribers (#1208). Since `@elgato/streamdeck` 3.0 the SDK event fires only for a PI's save, so without the promise path the one-time host migration would never get its answer. The SDK resolves that promise on the next frame, uncorrelated, so a PI save arriving while a read is pending would otherwise be delivered twice; both paths receive the same frame's settings object, and the promise's value is dropped when it is the event's last payload by reference. A throwing subscriber is logged and does not stop the rest. `useLegacySettingsBehavior` stays off — turning it on would deliver the reply twice — and lint refuses the property. See `.claude/rules/global-settings.md`.
- **Neo Infobar instances are narrowed out** — SDK 3.0's `WillAppearEvent` / `DidReceiveSettingsEvent` action includes `NeoInfobarAction`, which has no image or title. No manifest entry declares that controller, so the bridge returns early on `ev.action.isNeoInfobar()` (willAppear, didReceiveSettings) and `controllerType === "Neo"` (willDisappear, whose `ActionContext` has no discriminator method) rather than casting. Supporting Neo Infobar actions is a separate decision.
- **Other adapter methods** — Delegate directly to the Elgato SDK (`setGlobalSettings`, `onApplicationDidLaunch`, `connect`, etc.)

## Also Contains

- `createSDLogger()` / `SDLoggerLike` — Wraps Elgato's SDK logger into the `ILogger` interface with level filtering. Defaults to `LogLevel.Debug` intentionally: level gating happens at the `streamDeck.logger` layer, so the wrapper keeps forwarding debug and a runtime `debugLogging` flip surfaces scoped debug logs without recreating loggers (see `.claude/rules/logging.md`)
- `elgatoPluginLogFile(cwd?)` / `elgatoPluginUuid(cwd)` (#1330) — the file `@elgato/streamdeck`'s logger writes, `<cwd>/logs/<plugin UUID>.0.log`, which the SDK does not expose. The adapter reports it as its `logLocation`, which the shared bootstrap hands to the main-thread watchdog, whose worker appends to that file directly. `log-file.test.ts` checks the UUID against the SDK's own `getPluginUUID` and the path against a real `FileTarget`, so an SDK upgrade that moves the file turns the suite red

## Dependencies

- `@elgato/streamdeck` — The Elgato Stream Deck SDK
- `@iracedeck/deck-core` — Platform-agnostic interfaces
- `@iracedeck/app-constants` — `LogLocation`, the type `logLocation` reports (#1367)
- `@iracedeck/settings` — imported only by `adapter.test.ts`, which runs the real settings cache over the adapter's global-settings fan-out
- `@iracedeck/logger` — `ILogger` interface
