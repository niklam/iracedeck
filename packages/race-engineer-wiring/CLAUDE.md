# @iracedeck/race-engineer-wiring

The Race Engineer's wiring, in one place (#1349): the plugin-side bus caches the engine's conditions read (`caches.ts`), every one of `registerPitCrew`'s 34 dependencies (`pit-crew-deps.ts`; `pit-crew-deps.test.ts` pins the count, so a new one bumps both), the call (`wireRaceEngineer`), the sim's query side as the Race Engineer reads it (`sim-runtime.ts`) and the translator's settings-backed options (`translator-options.ts`, #1378). The three plugins reach it through `@iracedeck/plugin-runtime`'s `initRaceEngineer`; the scenario harness calls it directly, with its three snapshot stubs as `overrides`.

## Boundaries

- It imports `audio-scenarios`, `callout-settings`, `settings`, `event-bus`, `sim-events-iracing` and `logger`. `TelemetryData` comes through `sim-events-iracing`'s type re-export, so it imports no `iracing-sdk`. Neither `settings` nor `deck-core` imports it (the cycles run one way only). Settings, `isCalloutEnabled`, `evaluateSetupWarning` and `resolveActiveDriverName` come from `@iracedeck/settings` directly (#1365); nothing it provides is injected.
- It takes one `logger` and makes every logger it needs with `logger.createScope(...)`; the bootstrap passes `adapter.createLogger("RaceEngineer")`, so its lines print as `[RaceEngineer:LapCompleted]` and the like on Mirabox and Ulanzi, and as `RaceEngineer->LapCompleted` on Stream Deck, whose SDK joins scopes with `->`.
- `voice` is the voice-pack phase's driver-name state, read on every call (the harness passes its seeded list).
- `SimRuntime` (`sim-runtime.ts`) is every read the Race Engineer makes of the running sim, as one object: an interface declared member by member (23 since #1378), each member documented with what it answers before the translator starts, so its surface is that list and not whatever `sim-events-iracing` exports. Its only value imports are the getters `createIracingSimRuntime()` assembles, the one implementation (`isStandingStart` is the one member renamed, over the translator's `getStandingStart`); `sim-runtime.test.ts` pins the getters to the interface. Its payload types stay the translator's until #714's read model, and nothing a deck host needs goes on it (#1500 declares its own interface in `plugin-runtime`). `buildPitCrewDeps` fills every sim-reading dependency from it and from nothing else, and converts the one value the catalog spells differently: the translator's `TrackDirection` enum becomes the catalog's `SpotterTrackDirection` union through an exhaustive map. Three of its readers serve the pace lineup: `getPaceLineup` (the caution's and the formation's, #1127 / #1167), `getRollingStartFormation` (#1167) and `getCautionGap` (#1168), each passed to `registerPitCrew` as a live read the callouts ask at speak time.
- `createIracingTranslatorOptions()` (`translator-options.ts`, #1378) builds all six `initializeSimEventsIracing` options as live, sanitized reads of the global settings — the fuel margin, the corner lead, the gap threshold and consistency gate, the opponent-flag opt-ins (`isOpponentFlagCalloutEnabled`, typed against the bus's `OpponentPenaltyFlag`, an unmapped flag falling open) and the opponent-flag range. It returns `Required<SimEventsIracingOptions>`, so a new translator option fails `pnpm typecheck` here. `plugin-runtime`'s `initSim` and the scenario harness both call it, so the six settings apply in the harness as in the plugin.
- Every callout opt-in is one dependency, `isCalloutEnabled`, passed straight from `@iracedeck/settings` (#1350): each family in `registerPitCrew` resolves its own callout id to a key through `@iracedeck/callout-settings`, so a new callout needs no change here.

## Rules

- A new `PitCrewDeps` key fails `pnpm typecheck` until `buildPitCrewDeps` builds it (`Required<PitCrewDeps>`), so nothing is left to `DEFAULT_DEPS`.
- A new live sim read goes on `SimRuntime` first (with its no-translator value on the member and in `createIracingSimRuntime`), then on `PitCrewDeps` as a key `buildPitCrewDeps` fills from that member; the catalog never reaches the translator for it (`.claude/rules/race-engineer-callouts.md`).
- A cache the engine's `where:` clauses read is subscribed in `subscribeRaceEngineerCaches`, which runs before `registerPitCrew`.

## Build

`pnpm build` runs `tsc` into `dist/`, which is what its consumers resolve: the three plugin bundles, through `plugin-runtime` (raw TypeScript compiled into each bundle, whose import of this package resolves to `dist/`), and the scenario harness, whose `tsc` and runtime (`dev` and `start` alike) resolve it there, so build this package before running the harness. Tests run against `src/` through the root Vitest alias.
