# @iracedeck/deck-core

Platform-agnostic core interfaces, base classes, and utilities for deck device plugins. "Platform" here means the **deck-host ecosystem** (Elgato / Mirabox / Ulanzi): this package contains no deck-host-specific code — it defines the abstraction layer that the platform adapters implement. It is not an OS-abstraction boundary: iRaceDeck is Windows-only (iRacing is), and anything that needs the native addon stays injected from the plugin (`initializeKeyboard`, `initWindowFocus`, …).

It is also sim-neutral (#1351): the deck layer sees a simulator only through the `SimConnection` interface in `sim-connection.ts` (below), and everything iRacing-specific — the SDK singleton and `getCommands()`, the `SimIRacingAction` base that hands actions the typed SDK controller, the app monitor, the fuel and unit helpers, the hotkey presets, the elevation check and the replay-session subscriber — lives in `@iracedeck/deck-iracing`, which depends on this package and never the other way round. An ESLint `no-restricted-imports` rule on `packages/deck-core/src/**` refuses `@iracedeck/iracing-sdk`, `@iracedeck/iracing-native`, `@iracedeck/sim-events-iracing` and `@iracedeck/deck-iracing`, `scripts/deck-core-sim-boundary.test.mjs` proves it fires, and `iracing-sdk` is not a dependency, so even a type-only import fails to resolve. Spec: `docs/superpowers/specs/2026-10-07-issue-1351-deck-core-split-and-sim-seam.md`.

Two dependency-free leaves sit below it (#1364): `@iracedeck/app-constants` (setting-key names, the voice-pack status payload and catalog location, the changelog policies, the Focus iRacing Window modes, the Mouse to Sim pointer target, the key map and default-binding parser, the settings-window page name and warning ids, the `_warnings` record shape, and `LogLocation`, the type `IDeckPlatformAdapter.logLocation` reports, #1367) and `@iracedeck/fetch-utils` (`abortAfter`, `readCappedJson` / `ResponseTooLargeError`). deck-core imports `app-constants` and re-exports none of it, and it no longer has a `./key-binding-defaults` subpath: every name has one import path, so import a moved name from its leaf, and a test mocking deck-core never needs to cover it. deck-core no longer imports `fetch-utils` at all: its one consumer here, the changelog feed client, moved to `@iracedeck/app-updates` (#1367). Each leaf documents itself in its own `CLAUDE.md`.

`@iracedeck/settings` sits below it as well (#1365): the global-settings schema and cache, the migrations, the plugin-owned settings store, run-scoped keys, the PI warnings, the setup-warning and settings-file banners, first run and the feature-startup gates. deck-core imports it and re-exports none of its names, so an action or test reaches `getGlobalSettings`, `isCalloutEnabled`, `setWarning` and the rest through `@iracedeck/settings`, and a test that stubs one mocks that package — a `vi.mock("@iracedeck/deck-core")` cannot reach them. `IDeckPlatformAdapter` extends its `SettingsHost`. The module map is in `packages/settings/CLAUDE.md`.

The Race Engineer voice-pack stack is not here either (#1366): the scanner, the voice-pack service, the catalog and its client, download, archive extraction, storage, the installer, the launch step, the voice labels and the missing-callout-script banner are `@iracedeck/voice-packs`, which depends on neither this package nor `settings`. deck-core re-exports none of its names, nor the `@iracedeck/callout-script` names it used to re-export beside them (`parseVoicePackManifest`, `VoicePackManifestSchema`, `VOICE_PACK_MANIFEST_FILE`, `VOICE_SCRIPT_MAX_BYTES`, `CalloutScript`); import those from `@iracedeck/callout-script`. What deck-core still knows of voice packs is `plugin-config.ts`'s `getDevVoicePacksRoot()`; the settings window's voice-pack commands are `@iracedeck/settings-window`'s since #1367. The module map is in `packages/voice-packs/CLAUDE.md`.

Four more concerns left in #1367, the last of #1351's five PRs, each for a package of its own with its own `CLAUDE.md` and module map: the per-session replay store (`replay-session-store`, `replay-session-file`, `replay-markers`, `replay-laps`) is `@iracedeck/replay-store`; the main-thread watchdog, the resource monitor and the CPU profile capture are `@iracedeck/diagnostics`; the version check, the published-changelog feed, its sanitizer and the update check are `@iracedeck/app-updates`; and the settings window's server, guard, controller, launcher, command handler and failure banner, with `chromium-browser`, `open-folder` and the settings-channel publisher, are `@iracedeck/settings-window`. `audio-session-identity.ts` moved to `@iracedeck/plugin-runtime`, its only consumer. deck-core re-exports none of their names, so each is imported, and mocked in a test, from its own package; with them went deck-core's `semver`, `ws`, `fetch-utils` and `callout-script` dependencies. What is left here is the deck abstraction.

## Package Contents

### Platform Abstraction (`types.ts`)

- `IDeckActionContext` — Handle to a single action instance. Wraps `id`, optional `deviceId?`/`deviceType?` (populated by adapters that expose them — Elgato; used for profile switching, #736), `setImage`, `setTitle`, `setSettings`, `isKey`, optional `showAlert?()` (flashes the host's warning indicator where supported — Elgato keys only), and (for Stream Deck+ dials) `isDial()`, `setFeedback(feedback)`, `setFeedbackLayout(layout)`, `setTriggerDescription(descriptions)` (takes a `DeckTriggerDescription`). `setFeedback`/`setFeedbackLayout`/`setTriggerDescription` no-op on platforms/controllers without a plugin-drawable touch strip (e.g. Mirabox). The dial's own screen goes through `dialCanvas()` (a `DialCanvasProfile`, or `null` on a key, an Information context, or a host with no dial screen) and `setDialCanvas(dataUri)` (one full-canvas image; a no-op when `dialCanvas()` is `null`) — #1013, see `dial-canvas.ts` below.
- `IDeckEvent<T>` and variants (`IDeckKeyDownEvent`, `IDeckWillAppearEvent`, etc.) — Platform-neutral events. Dial/touch variants: `IDeckDialRotateEvent` (carries signed `ticks` and `pressed: boolean` — whether the dial button was held during rotation, the basis of push+turn), `IDeckDialDownEvent`, `IDeckDialUpEvent`, and `IDeckTouchTapEvent` (carries `tapPos: [x, y]` and `hold: boolean`).
- `IDeckActionHandler<T>` — Interface for action lifecycle handlers (includes `onDialRotate`/`onDialDown`/`onDialUp`/`onTouchTap`).
- `IDeckPlatformAdapter` — Interface that platform adapters implement (Elgato, VSDinside, etc.). It extends `@iracedeck/settings`' `SettingsHost` (#1365), which declares the global-settings members: `onDidReceiveGlobalSettings`, `getGlobalSettings`, `setGlobalSettings` and the optional `onHostReady?` (#1056) — optional on purpose, because only the WebSocket adapters can report a socket opening, and Elgato declares nothing rather than stubbing it, since absence means "the deadline already armed is honest" for a transport that queues the read until it can be sent. Its own members are mostly required. `openUrl`, `onOpenSettingsRequest`, `setLogLevel` and `logLocation` (`LogLocation | undefined`) are interface members since #1349; the shared bootstrap (`@iracedeck/plugin-runtime`) reads them. `LogLocation` itself is `@iracedeck/app-constants`' since #1367 (the watchdog in `@iracedeck/diagnostics` writes to it too, so it lives below both), and deck-core does not re-export it.

### Encoder Touch-Strip Feedback (`feedback-types.ts`)

- `DeckFeedbackPayload` — Platform-neutral Stream Deck+ touch-strip feedback payload passed to `IDeckActionContext.setFeedback`, keyed by layout item `key`; values are primitive shorthands or partial item overrides (`DeckFeedbackBarItem` / `DeckFeedbackTextItem` / `DeckFeedbackPixmapItem`). Details + platform caveats in `.claude/rules/encoders-and-touchscreen.md`.

### Base Classes

- `BaseAction<T>` — Abstract base with SVG image management, flag overlay, inactive state tracking, and the title-template live watcher (#899): contexts whose user-entered `titleOverrides.titleText` contains `{{` share one sim-connection subscription that re-resolves the template per tick, string-compares, and re-runs the context's regenerate callback through a 10 Hz `IconUpdateThrottle` — so any action that registers `setRegenerateCallback` gets live templated titles for free. Both the overlay and the watcher read the sim through `getSimConnection()` — the overlay pulls `activeFlags()` on each tick, the watcher `resolveTitleTemplate()` — and both simply subscribe: one made before the sim connection exists is queued and replayed when it is initialised (see `sim-connection.ts` below). A tick whose `activeFlags()` throws is skipped and the previous flag state kept, rather than read as the flags clearing, so a transient failure neither flickers the overlay nor re-arms a flash the duration setting already ended. Accepts logger via constructor. Implements `IDeckActionHandler<T>`.
- `ConnectionStateAwareAction<T>` — Extends `BaseAction` with automatic sim connection tracking through `getSimConnection()`: each context subscribes on appear and re-evaluates its readiness on every tick, from `isConnected()` and, for an action tracking bindings, the binding dispatcher. An action that appears before a sim connection is initialised loses nothing: its subscription is queued and replayed onto the connection at initialisation. It has no `sdkController` (#1351): an action that reads iRacing telemetry or session info directly extends `@iracedeck/deck-iracing`'s `SimIRacingAction` instead. Also home of the binding-dispatch delegates: `setActiveBinding`, `tapBinding` (resolves to whether the press went out, #962), `tapBindingSequence` (atomic multi-chord sequence, #818), `holdBinding`, `releaseBinding`, `isBindingMissing` (per-context missing-binding check — prefer it over the shared `isActiveBindingMissing()`), and `isBindingKeyboardBound` (keyboard binding, not a SimHub role, #962).

### Sim Connection (`sim-connection.ts`)

- `SimConnection` — the deck layer's whole view of a simulator (#1351): `isConnected()`, `subscribe(id, onTick)` / `unsubscribe(id)` (`onTick(isConnected)` runs once per sim tick and on connection changes), `activeFlags()` (`readonly OverlayFlag[]` in priority order as of the latest tick, empty when none are out, the sim is disconnected or no tick has been seen) and `resolveTitleTemplate(text)` (a disconnected sim renders variables empty and leaves parse errors verbatim). `OverlayFlag` is `{ label, color, textColor, pulse }`, the shape the key overlay draws. Commands, telemetry and session info are deliberately not on it: they are the sim's vocabulary and stay in its own deck package (the sim-neutral read model is #714).
- The singleton trio `initializeSimConnection` (throws on a second call) / `getSimConnection` / `isSimConnectionInitialized`, plus `_resetSimConnection` for tests. Before initialisation `getSimConnection()` returns a frozen pending connection — never connected, no flags, title text returned as the user typed it (there is no template engine without a sim) — whose `subscribe(id, onTick)` records the subscription in a module-level queue and whose `unsubscribe(id)` removes it. `initializeSimConnection(c)` sets the connection, subscribes every queued entry on `c` in insertion order and clears the queue, so a key that appears before the sim connection exists loses nothing and callers need no `isSimConnectionInitialized()` check. Once a connection is set the pending one delegates every method to it, so a reference kept from before still works. `_resetSimConnection()` clears the connection and the queue. `isSimConnectionInitialized()` stays for `deck-iracing`'s `initializeSDK`, which refuses to run when a connection is already installed.
- The implementation is installed by the sim's deck package: `@iracedeck/deck-iracing`'s `initializeSDK` constructs `SimIRacingConnection` and initialises it. A second sim is a sibling `deck-<sim>`, chosen in `plugin-runtime`.
- `fake-sim-connection.ts` — `createFakeSimConnection()`, a scriptable connection for this package's tests (`state`, `subscribers`, `tick()`); not exported from the barrel, imported by relative path.

### Icon Assembly (re-exported from `@iracedeck/icon-composer`)

Pure icon assembly functions (assembleIcon, extractGraphicContent, generateTitleText, resolveBorderSettings, resolveGraphicSettings, resolveIconColors, etc.) have been moved to the standalone `@iracedeck/icon-composer` package (zero dependencies). They are re-exported from `deck-core` for backward compatibility — existing imports from `@iracedeck/deck-core` continue to work.

**Exception:** `resolveTitleSettings` is no longer a pure re-export (#899) — deck-core's `title-settings.ts` wraps icon-composer's pure function and template-resolves the user-entered `titleOverrides.titleText` through the sim connection's `resolveTitleTemplate` (`title-template.ts`). Always import it from `@iracedeck/deck-core`, never from `@iracedeck/icon-composer` directly, or titles lose template support.

deck-core adds global settings readers on top of the pure functions:

- `getGlobalTitleSettings()` — reads title defaults from global settings store
- `getGlobalBorderSettings()` — reads border defaults from global settings store
- `getGlobalGraphicSettings()` — reads graphic scale default from global settings store

### Shared Utilities

- `common-settings.ts` — `CommonSettings` Zod schema (flagsOverlay, colorOverrides, titleOverrides, borderOverrides, graphicOverrides)
- `migrate-legacy-action.ts` — `migrateLegacyActionToMode` settings-migration helper
- `keyboard-service.ts` — Keyboard singleton (`initializeKeyboard`, `getKeyboard`); since #977 every path that actually emits calls `focusIRacingBeforeInput()` immediately before the native send — `sendKey` plus the scan-code and keysender helpers behind `sendKeyCombination` / `pressKeyCombination` / `sendKeySequence`, never a release — so a skipped sequence focuses nothing, every keystroke deck-core emits focuses from one layer, and a direct `getKeyboard()` caller needs no focus call of its own
- `clipboard-service.ts` — Clipboard singleton with injected writer (`initializeClipboard`, `getClipboard`); mirrors the keyboard-service DI pattern
- `simhub-service.ts` — SimHub Control Mapper singleton (`initializeSimHub`, `getSimHub`) plus the reachability API (`isSimHubReachable`, `onSimHubReachabilityChange`)
- `icon-template.ts` — SVG template rendering and color resolution (delegates to `@iracedeck/icon-composer`)
- `title-template.ts` — User-entered title template resolution (#899): `titleHasTemplate` (the cheap `{{` gate) and `resolveTitleTemplate`, which hands text containing `{{` to `getSimConnection().resolveTitleTemplate` and returns the text as typed if the connection throws, so it never throws inside the sim's subscriber fan-out. With no sim connection yet, and if the connection throws, the text is returned as the user typed it. The disconnected fallback (variables render empty, expression parse errors stay verbatim) is the sim's: iRacing's is `EMPTY_TEMPLATE_CONTEXT` in `@iracedeck/deck-iracing`
- `icon-update-throttle.ts` — `IconUpdateThrottle`, the per-context 10 Hz throttle + trailing-edge coalescer for telemetry-driven `setKeyImage` bursts (#493; moved here from `iracing-actions/src/shared/` in #899 so the `BaseAction` title watcher can use it)
- `overlay-utils.ts` — SVG overlay utilities (inactive state, data URI conversion)
- `key-binding-utils.ts` — Key binding parsing and formatting
- `comm-descriptor.ts` — The #612 per-mode `CommDescriptor` types + `keybind` / `keybindBy` / `keybindKeys` / `keybindFixed` helpers, consumed by iracing-actions' `comms-catalog.ts`
- `dial-canvas.ts` — The dial-screen profiles (#1013), a description of hardware that knows no sim and no host: `DialCanvasProfile` (`id: "sd-plus-strip" | "stream-dock-knob"`, `width`, `height`), `SD_PLUS_STRIP_CANVAS` (200×100, one encoder's slot of the Stream Deck+ strip), `STREAM_DOCK_KNOB_CANVAS` (176×112, the LCD segment above a Stream Dock knob), and `DIAL_CANVAS_KEY = "box"` (the pixmap key every Elgato dial layout uses). Adapters decide which profile a context has; renderers branch on `id`, never on the platform. `toDeviceImage` (`rasterizer-service.ts`) takes a square size or a non-square `{ width, height }` target for the knob; see `.claude/rules/encoders-and-touchscreen.md`.
- `dial-gesture.ts` — Shared dial-gesture convention: `classifyDialRelease` (release-time press classifier, `DIAL_LONG_PRESS_THRESHOLD_MS`) plus `resolvePairedAction` / `DirectionalPair` (Push+Turn pair dispatch); see `.claude/rules/encoders-and-touchscreen.md`
- `keyboard-types.ts` — Keyboard type definitions
- `scan-code-map.ts` — PS/2 scan code mapping
- `device-profiles.ts` — Canonical Stream Deck device + profile reference (#736, #753, #790): `DeviceType`, `DEVICE_SPECS`, `DEVICE_SUPPORT`, `PROFILE_NAMES` / `PROFILE_TARGET_DEVICES` / `PROFILE_NAV_ACTIONS`, `CAR_SELECTOR_PROFILE`, `shipsBundledProfiles`, lookup helpers, and the device-suffixed profile-name helpers (`PROFILE_DEVICE_SUFFIXES`, `profileDeviceSuffix`, `deviceProfileName`, `profileDisplayName`, `resolveProfileNameForDevice`); details in `.claude/rules/profiles-and-devices.md` (Elgato-only)
- `profile-switcher.ts` — Profile-switch singleton (#736): `requestProfileSwitch`, `requestProfileSwitchBack`, `notifyProfileVisible` — the layer above the adapters' `switchToProfile`; a safe no-op where unregistered (non-Elgato)

- `window-focus-service.ts` — Window focus singleton (#930): `initWindowFocus`, `focusIRacingIfEnabled`, `focusIRacingBeforeInput`, `focusIRacingNow`, `FocusResult`, `FOCUS_TIMEOUT_COOLDOWN_MS`, `_resetWindowFocus`. The plugins' shared bootstrap (`plugin-runtime`'s `registerActions`) injects the focuser (same DI shape as `keyboard-service`), so deck-core never imports `@iracedeck/iracing-native` — importing that package loads the native addon as a module side effect. `FocusResult` is therefore a hand-kept **mirror** of the native enum; `packages/iracing-plugin-stream-deck/src/shared/focus-result.test.ts` asserts the two stay identical. It also injects `deck-iracing`'s two iRacing checks: the app monitor's `isIRacingActive` as `initWindowFocus`'s third argument (`SimRunningCheck`, the warn-vs-debug choice for `WindowNotFound`), first injected because importing it here closed the cycle `sdk-singleton` → `window-focus-service` → `app-monitor` → `sdk-singleton` (#1176) — a cycle among workspace sources now fails the plugin builds — and `hasElevationMismatch` as the fourth (`ElevationMismatchCheck`, #1351), since deck-core imports no sim package. A check that throws reads as `false`. Previously duplicated in all three plugins' `src/shared/window-focus.ts`. Since #977 the setting is a three-value **mode** rather than a switch (`FocusIRacingMode` and its parser are in `@iracedeck/app-constants`), and the service has two gated call sites: `focusIRacingIfEnabled()` is the adapter-level one `plugin-runtime`'s `registerActions` registers on the key/dial events, and runs under `always` only; `focusIRacingBeforeInput()` is the keystroke one and runs under `always` and `required`, called from the keyboard service immediately before every native key emit and — via the `beforeKeystrokes` hook `deck-iracing`'s `initializeSDK` injects into `createSDK` — from `ChatCommand.sendMessage`; the Chat action's Open Chat and Reply modes call it directly too, since the prompt they open is for the driver to type into. Both skip the native ask outright while the injected elevation check reports a mismatch (#976), and for `FOCUS_TIMEOUT_COOLDOWN_MS` after a `FocusTimedOut`, so the doubled ask under `always` cannot double the focuser's ~1 s wait while an elevation mismatch is making every press time out. `focusIRacingNow()` (#926) is the unconditional variant for action code where focusing IS the pressed action — it skips the mode (it focuses even under `never`), the `isSettingsStoreReady()` gate, the mismatch gate and the cooldown alike, and shares the gated path's result handling.
- `mouse-pointer-service.ts` — Mouse pointer singleton (#926): `initMousePointer`, `movePointerToSim`, `PointerMoveResult`, `DEFAULT_POINTER_X_FRACTION` / `DEFAULT_POINTER_Y_FRACTION`, `_resetMousePointer`. Deliberately a SIBLING of the focus service rather than part of it — one owns the foreground, the other owns where the pointer goes, and neither needs the other. Same injected-delegate shape and the same hand-kept native mirror, guarded by `pointer-move-result.test.ts`. Composing the two (focus, then move) is feature policy and lives in `@iracedeck/iracing-actions`' `shared/mouse-to-sim.ts`. The two `DEFAULT_POINTER_*_FRACTION` constants remain the no-argument fallback; since #1029 the target callers actually pass comes from `resolveSimPointerTarget` in `@iracedeck/app-constants`, whose defaults resolve to exactly these two (pinned in `mouse-pointer-service.test.ts`; `sim-pointer-target.partial.test.ts` pins the settings-window control's `default=` attributes to the same constants).

## Build

```bash
pnpm build  # tsc → dist/
```

Pure TypeScript library, no Rollup needed. Outputs ESM with declarations.

## Dependencies

- `@iracedeck/app-constants` — Shared setting keys and value sets (zero-dependency, #1364), and `LogLocation`, which `IDeckPlatformAdapter` names (#1367)
- `@iracedeck/settings` — Global settings, the settings store, PI warnings and the startup gates, and the `SettingsHost` that `IDeckPlatformAdapter` extends (#1365)
- `@iracedeck/icon-composer` — Pure icon assembly functions (zero-dependency)
- `@iracedeck/logger` — For `ILogger` interface
- `zod` — For settings schemas
- `keysender` — `optionalDependencies` only, and imported by nothing at compile time (#1177). `keyboard-service.ts` loads it at runtime through a variable module name (Windows-only native module; its types are defined locally), from each plugin's `bin/node_modules`. The declaration exists so Dependabot can see it and `scripts/lib/runtime-deps.mjs` has a version to ship in the plugins' `bin/package.json`; it is declined in `allowBuilds` (`pnpm-workspace.yaml`), so a workspace install downloads it without compiling it (its install script is `node-gyp rebuild`). See `.claude/rules/plugin-structure.md`.
