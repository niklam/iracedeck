Every callout a voice pack's `callouts.json` may script, keyed by the id you write under `scenarios`. Each entry below is half code and half script: the description, trigger, frame, weight and scheduling come from the callout's contract in iRaceDeck's code — the part a pack cannot change — and **Says** and **Hear it** are the `comment` and `test` lines of the reference voice — `default`, the voice iRaceDeck publishes. Every **Hear it** line starts with the **scenario harness** — the tool in the iRaceDeck repository that fires a callout through the real engine without iRacing; the [tutorial](/docs/voice-packs/first-pack/#hear-it-in-the-harness) has the command that starts it and the `IRACEDECK_VOICE_PACKS_PATH` variable that makes it load your pack. The references at the end are what that entry draws on, its included fragments walked, so you can see which lines to record and which [vocabulary](/docs/voice-packs/reference/vocabulary/) it names; a pool links to its line on the [recording script](/docs/voice-packs/reference/recording-script/).

Callouts are grouped by **family**. Callouts in one family preempt each other whatever their weights, so a newer one replaces a family-mate that is still playing; the callouts with no family come last. When a callout stays silent in your voice, read its description and its **Hear it** line before touching your entry — a callout is triggered by the code, and your entry is consulted only after that trigger has fired. See [A correct script can be silent](/docs/voice-packs/#a-correct-script-can-be-silent).

This page is generated from the code and the reference voice's script, and a test fails when the two drift apart, so it matches the release it documents.
