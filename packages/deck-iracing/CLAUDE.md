# @iracedeck/deck-iracing

iRacing's side of the deck layer's sim-connection seam (#1351). `@iracedeck/deck-core` is sim-neutral and sees a simulator only through its `SimConnection` interface; this package implements that interface over the iRacing SDK and holds everything else in the deck layer that speaks iRacing: the `SimIRacingAction` base for actions that read the SDK directly, the SDK singleton behind `getCommands()`, and the iRacing helpers actions and the plugin bootstrap share. It depends on `deck-core`, never the other way round — a lint rule on `packages/deck-core/src/**` refuses any import of this package, `iracing-sdk`, `iracing-native` or `sim-events-iracing` there (`scripts/deck-core-sim-boundary.test.mjs` proves it fires).

It has the same shape `@iracedeck/sim-events-iracing` has on the bus side: a second sim is a sibling `deck-<sim>` implementing the same `SimConnection`, chosen in `@iracedeck/plugin-runtime` and nowhere else. Spec: `docs/superpowers/specs/2026-10-07-issue-1351-deck-core-split-and-sim-seam.md`.

**Naming:** a sim's deck-layer classes are named `Sim<Game>…` — `SimIRacingAction`, `SimIRacingConnection` here, and a future `deck-<sim>` would export `SimAssettoCorsaAction` / `SimLmuConnection` and so on. The prefix keeps the game in the name while stopping `IRacing…` from reading as an `I`-prefixed interface, which is how this repo names interfaces (`IDeckPlatformAdapter`, `ILogger`). The older `IRacingSDK`, `IRacingNative` and `IRacingHotkeyPreset` predate the rule and are left as they are.

## Package Contents

### The seam

- `sim-iracing-connection.ts` — `SimIRacingConnection`, the `SimConnection` over an `SDKController`. `isConnected()` is the controller's connection status; `subscribe(id, onTick)` wraps the controller's subscription and records each tick's telemetry (null on a disconnected tick), so `activeFlags()` maps the latest tick's `SessionFlags` through `resolveAllActiveFlags` without a telemetry read of its own — the tick already did one. The recorded telemetry is connection-wide and meant to be read inside a tick; before any tick, and while disconnected, `activeFlags()` returns no flags. `resolveTitleTemplate(text)` resolves against the controller's per-tick template context and falls back to `EMPTY_TEMPLATE_CONTEXT` when there is none or it throws. `EMPTY_TEMPLATE_CONTEXT` is the frozen disconnected context — `{{variable}}` placeholders render empty and `{{= expression }}` parse errors stay visible, the rules Telemetry Display values follow — exported for any other display path that reads `getCurrentTemplateContext()` itself (Chat's key text, #1337) so it falls back the same way.
- `sim-iracing-action.ts` — `SimIRacingAction<T>`, `deck-core`'s `ConnectionStateAwareAction<T>` plus `protected get sdkController(): SDKController` (the singleton's controller). **Extend it only when the action reads iRacing directly** — `getCurrentTelemetry`, `getSessionInfo`, `getCurrentTemplateContext`, or its own `subscribe` for telemetry-driven icons; every other action stays on `ConnectionStateAwareAction`, which already tracks readiness through the sim connection. Calling `getCommands()` alone does not need it. The class is where an action's direct dependency on iRacing is named, so the leak the Architecture page lists under "Seams & where the abstraction leaks" is one import away from being found; porting those reads is #714's read model.
- `sdk-singleton.ts` — the iRacing SDK singleton: `initializeSDK(logger)` (once, at startup; throws on a second call, and throws before creating anything when a sim connection is already installed, so a refused call leaves the SDK uninitialised rather than half-initialised), `getSDK`, `getController`, `getCommands`, `isSDKInitialized`, `_resetSDK`. `initializeSDK` also constructs `SimIRacingConnection` over the new controller and calls `deck-core`'s `initializeSimConnection`, so the deck layer's connection exists from the same call, and injects `deck-core`'s `focusIRacingBeforeInput` as `createSDK`'s `beforeKeystrokes` hook (the chat command types; every other command broadcasts, #977). `_resetSDK` resets the sim connection too. `getCommands()` is the iRacing-shaped command surface actions use (camera, replay, chat, pit, video capture, texture, telemetry); a sim-neutral one is #714.

### iRacing helpers

- `app-monitor.ts` — iRacing process detection: `initAppMonitor(adapter, logger)` (takes `IDeckPlatformAdapter`; requires `initializeSDK()` first), `isIRacingRunning()`, `isIRacingActive()` (running-flag OR live SDK connection) and the `onIRacingTerminated(listener)` subscription, whose listeners run after the running flag and SDK connection are already down (#870), with its counterpart `onIRacingStarted(listener)` (#1338): once per session, on the first of the launch event and the SDK connection coming up, re-armed by the exit notification. Exit detection is dual-path: the host terminate event, plus an SDK-disconnect fallback (`IRACING_EXIT_SDK_CONFIRM_MS`, 5 s sustained loss) for hosts that never deliver app-monitoring events — deduped per exit episode, blip-safe when a launch event affirmed the sim is running. Adapters that never deliver launch/terminate events declare `supportsApplicationMonitoring = false` on `IDeckPlatformAdapter` (Ulanzi); the app monitor then keeps SDK reconnect polling enabled at startup instead of pausing it until a launch event that would never come. `deck-core`'s window focus service, resource monitor and version check take these as injected delegates rather than importing them (#1176), which `plugin-runtime` wires.
- `elevation-warning.ts` + `elevation-check.ts` — Administrator/integrity mismatch detection (#610, #902): the pure `evaluateElevationWarning` (structurally typed, no native dependency) plus `createElevationCheckSubscriber`, the once-per-connection `sdkController` subscriber `plugin-runtime` wires with the native probe as `getStatus` (`native.getElevationStatus()`) — logs warn on a mismatch, info on a pass (so support logs capture the outcome at the default level), status detail at debug, and posts/clears the PI banner. It also keeps the current connection's verdict for `hasElevationMismatch()` (cleared on disconnect and on a probe that throws), which `plugin-runtime` injects into `deck-core`'s `initWindowFocus` as its fourth argument (`ElevationMismatchCheck`, #1351) so the focus service skips a focus that cannot succeed (#976) — never to gate an action.
- `replay-session-subscriber.ts` — `createReplaySessionSubscriber({ store, getSessionInfo, logger })`, an `sdkController.subscribe` callback in the elevation-check shape that reads `WeekendInfo` (`replaySessionHeaderFromSessionInfo`) and calls `@iracedeck/replay-store`'s `setActiveSession` / `clearActiveSession` (#1162); the store itself knows files and nothing about telemetry.
- `fuel-telemetry.ts` — `isFuelFillOn` / `isPitstopActive` / `isAutofuelActive` / `isAutofuelEnabled`, the telemetry readers both Fuel Service surfaces (keypad + dial) share. `sim-events-iracing`'s `toggles.ts` inlines the `isAutofuelActive` rule because that package does not depend on the deck layer.
- `unit-conversion.ts` — fuel unit conversion over iRacing's `DisplayUnits` (`fuelToDisplayUnits`, `fuelFromDisplayUnits`, `getFuelUnitSuffix`, `formatFuelAmount*`, …), plus `celsiusToFahrenheit` for temperature readouts.
- `iracing-hotkeys.ts` — iRacing's default keyboard shortcuts as presets (`IRACING_HOTKEY_PRESETS`, `getHotkeyPreset`, `getHotkeysByCategory`); the `IRacingHotkeyPreset` type stays in `deck-core`'s `keyboard-types.ts`.

## Testing

The tests here moved with their modules (`app-monitor`, `sdk-singleton`, `iracing-hotkeys` and `unit-conversion` came from `iracing-plugin-stream-deck/src/shared/`). The root `vitest.config.ts` aliases `@iracedeck/deck-iracing` to this package's source. In an action test, mock this package with `importOriginal` and override only the names the test drives (`getCommands`, the fuel and unit helpers), keeping the `deck-core` `ConnectionStateAwareAction` mock whose `sdkController` field shadows `SimIRacingAction`'s getter — see "Action Test Structure" in `.claude/rules/testing.md`.

## Build

```bash
pnpm build  # tsc → dist/
```

Pure TypeScript library, no Rollup needed. Outputs ESM with declarations.

## Dependencies

- `@iracedeck/deck-core` — the `SimConnection` interface and its singleton, `ConnectionStateAwareAction`, the focus hook
- `@iracedeck/replay-store` — the `ReplaySessionStore` and `ReplaySessionHeader` types the replay-session subscriber writes to (#1367)
- `@iracedeck/settings` — the PI warning banner (`setWarning`, `clearWarning`) the elevation check raises
- `@iracedeck/app-constants` — `PiWarning`, the banner record `evaluateElevationWarning` returns (#1366)
- `@iracedeck/iracing-sdk` — `createSDK`, `SDKController`, the telemetry and session types, `resolveAllActiveFlags`, `resolveTemplate`, `PitSvFlags`, `DisplayUnits`
- `@iracedeck/logger` — For the `ILogger` interface
