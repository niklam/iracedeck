# @iracedeck/replay-store

The per-session replay store (#1162, #1203), moved out of `deck-core` in #1367 (spec #1351, `docs/superpowers/specs/2026-10-07-issue-1351-deck-core-split-and-sim-seam.md`): the replay markers and the lap record, one file per `SubSessionID` under `%LOCALAPPDATA%\iRaceDeck\Replay\<ecosystem>`, written debounced and atomically. It depends on `@iracedeck/settings` (the path helpers `resolveLocalAppData`, `nonBlank` and `settingsStoreFolderName`, and the settings store's `WRITE_RETRY_DELAYS_MS` schedule) and `@iracedeck/logger`, and on nothing sim-shaped: the store knows files, never telemetry. Three packages depend on it: `deck-iracing` (the replay-session subscriber, which takes the store and its `ReplaySessionHeader` type), `iracing-actions` (Replay Markers, and Replay Control's Jump to Fastest Lap) and `plugin-runtime` (the settings phase creates and initialises it, wires its exit flush and feeds it the lap events; `src/types.ts` names `ReplaySessionStore`).

## What reaches it, and from where

The store is fed from two directions. `deck-iracing`'s replay-session subscriber, which `plugin-runtime`'s `startServices` puts on the SDK controller, reads `WeekendInfo` and calls `setActiveSession` / `clearActiveSession`. The laps come over the bus: `sim-events-iracing`'s replay-laps diff publishes `replay.lapStarted` / `replay.lapTimed`, and `initSettings` subscribes to both and hands them to `laps.recordLapStart` / `laps.recordLapTime`. The actions read the store synchronously through `getReplaySessionStore()`.

One file outside the package reaches a source by relative path rather than through the barrel: `iracing-actions`' `replay-markers-dial-surface.test.ts` loads `src/replay-markers.ts` with `vi.importActual` past its own mock of the barrel, so its fake store answers next / previous / add / delete exactly as the real one does (the module has no imports). A rename or move of `replay-markers.ts` breaks it.

## Module map

- `replay-session-file.ts` — the file: `resolveReplayStoreDirectory({ platform, env })` (`%LOCALAPPDATA%\iRaceDeck\Replay\<ecosystem>`, the ecosystem folder from `@iracedeck/settings`' `settingsStoreFolderName` — per ecosystem because two deck hosts run two plugin processes that would otherwise rename their copies over each other every debounce; `IRACEDECK_REPLAY_DIR` replaces the `Replay` base and the ecosystem folder is still appended), `replaySessionFileName`, `parseReplaySessionFile` and the envelope type (`version`, `subSessionId`, `track`, `series`, `sessionStart`, `sections`). `REPLAY_FILE_FRAME_LAG` (59) records the measured `.rpy` lag and is deliberately not applied.
- `replay-markers.ts` — the pure marker logic: `addMarker` with the 60-frame dedupe, `deleteNearestMarker` within 600 frames, `nextMarker` past 60 ahead, `previousMarker` past 120 behind (the windows are the exported `MARKER_*_FRAMES` constants), `normalizeMarkers`, and `partitionMarkers`, which keeps a `markers` entry that is not a marker aside so it is re-emitted after the markers on every write.
- `replay-laps.ts` — the pure lap-record logic: `recordLapStartInSection` / `recordLapTimeInSection` (a time arriving before its start is held in memory and paired when the start comes), `findLapStartInSection` → `LapStartLookup`, `mergeLapsSectionInto`, `normalizeLapsSection`, `isNewerLapsSection` and `LAPS_SECTION_VERSION`. Which session a start joins and which one a lookup reads is the rule on `recordLapStartInSection`: a start with no pair match joins the one session with that `sessionNum` when its frame lies within the span of that session's recorded lap starts (the walk recording under a saved replay's own pair), else opens a new session (a restart's laps fall past the old span); a lookup whose pair-matched session lacks the car or the lap reads the one other session with the `sessionNum` that has both, `matchedBy: "sessionNum"`.
- `replay-session-store.ts` — the store: `createReplaySessionStore` and the singleton trio `initializeReplaySessionStore` / `getReplaySessionStore` / `isReplaySessionStoreInitialized` (`_resetReplaySessionStore` for tests). Described below.

The pure section logic is exported for tests and the harness.

## The store

The only owner of `%LOCALAPPDATA%\iRaceDeck\Replay\<ecosystem>\session_<SubSessionID>.json`. On init it removes stale `session_*.json.<pid>[.sync].tmp` files a crash left, and nothing else. Every plugin wires `process.on("exit", () => store.flushSync())` beside the settings store's (`plugin-runtime`'s `initSettings`). The file's sections are owned by features — `markers` and `laps` are the two this build reads (`REPLAY_MARKERS_SECTION`, `REPLAY_LAPS_SECTION`), and **every other key is preserved on every write**.

Same write discipline as `@iracedeck/settings`' `settings-store.ts` (atomic temp+rename; a trailing debounce `REPLAY_STORE_WRITE_DEBOUNCE_MS` 2 s capped by `REPLAY_STORE_WRITE_MAX_WAIT_MS` 10 s from the first unsaved change, so a field that never goes quiet still lands; a failed write goes back to pending — the active record itself IS the pending payload, so a retry writes whatever the record holds by then and never an older snapshot over a newer landed write, and a failed write for a session that has since changed is retried per path — on `WRITE_RETRY_DELAYS_MS` and kept for the shutdown flush; a corrupt file moved aside as `session_<id>.corrupt-<iso>.json`, the copy fallback skipping an identical aside so a locked file is preserved once and not once per open; compact JSON, because a race's record reaches megabytes and is rewritten every few seconds), with two differences: the load is SYNCHRONOUS (`setActiveSession` reads the file in the same tick the session appears, so the actions never see a loading state) and the pending write is flushed immediately on session change and disconnect.

- **Offline and unreadable sessions.** `SubSessionID` 0 (offline) is an in-memory record that is never written and is dropped on disconnect or the next session key. A session whose file could not be READ (a lock, a permission) opens in memory too, write-inhibited, and the read is retried on the same `WRITE_RETRY_DELAYS_MS` schedule (option `loadRetryDelaysMs`), then on a same-id `setActiveSession`, on the record's drop and in `flushSync`; once readable, the in-memory record is merged INTO the file — markers as a union under the dedupe rule, laps by `mergeLapsSectionInto` (the file's entry stays where both have one; a null `timeMs` is filled) — and written normally. A corrupt file that could not be preserved stays write-inhibited for the connection, because the next write would otherwise rename a near-empty record over bytes the store never saw — fail closed, as the settings store does for a corrupt file it cannot move.
- **Forward compatibility.** Every envelope field and every field on a marker, lap entry, car record or laps session that this build does not read is carried through a write (index signatures on the types); a `markers` entry that is not a marker is kept aside and re-emitted (`partitionMarkers`); and a `laps` section whose `version` is above `LAPS_SECTION_VERSION` (`isNewerLapsSection`) is a section this build has no reader for — carried through verbatim, `recordLapStart` / `recordLapTime` return false with one warning, and `findLapStart` misses with `newer format`.
- **The two APIs.** `markers` (`add`, `deleteNearest`, `next`, `previous`, `list`, under the windows above; `list()` returns a copy) and `laps` (`recordLapStart` / `recordLapTime`, and `findLapStart` → `LapStartLookup`, a hit with `matchedBy: "pair" | "sessionNum"` or a miss whose `reason` is the phrase the action logs: `no file` / `no session` / `no car` / `car mismatch` / `lap not recorded` / `newer format`). A laps call carrying a `subSessionId` other than the active record's is ignored (`SubSessionScoped`), and every markers call takes the same scope as an optional second argument. `findLapStart` answers `no file` when the record was neither loaded from disk nor written to — the plugin was not running for that session — and `no session` only for a record that exists without a matching session.

Specs: `docs/superpowers/specs/2026-09-13-issue-1162-replay-markers.md`, `2026-09-24-issue-1203-fastest-lap-from-session-record.md`.

## One import path per name

The barrel `src/index.ts` is the package's only entry, and deck-core re-exports none of it: import every name it exports from `@iracedeck/replay-store`, and mock that package in a test that stubs one (the Replay Markers and Replay Control tests do; `plugin-runtime`'s settings-phase and order tests mock it through `recordedModule`).
